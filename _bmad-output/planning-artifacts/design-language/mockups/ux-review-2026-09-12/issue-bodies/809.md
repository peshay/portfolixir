## Scope

`PATCH /api/v1/transactions/:id` and the MCP tool `portfolixir.transactions.update` exist; the Transactions LiveView has neither an edit nor a delete path — a mis-booked row is corrected by an agent over the API or MCP. The two-way coverage rule ("API And MCP Coverage") is about both users seeing everything; the update API predates that rule (2026-08-12), so no close-out has recorded the gap, and the Sprint 12 close-out opens the ledger with it. Target: "Bearbeiten" in the row menu of the history opens the booking in the drawer that #803 builds for creation (variant C, picked 2026-09-14) — same fields, same validation, the sell-lot preview against the remaining lots — and saving carries the ledger's rules (`Ledger.update_transaction/3`; a dividend's gross amount is the net cash credited). The history has no row menu today; this story adds it per the Tables pattern, or reuses the one #803 lands.
