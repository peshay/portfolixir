Nicht Teil der Wahl — was für alle drei Varianten gilt

  1. Eine Ansicht, die eine Regel gelesen hat, bleibt gesperrt, solange die Regel besteht. Das gilt, egal ob die Regel die Ansicht als Kontext oder als Bezug liest. Solange die gültige Version sie nennt, lässt sie sich ohnehin nicht löschen. Aber auch Beenden gibt sie nicht frei, denn Beenden stoppt nur die Auswertung. Eine Version, die gegolten hat, behält ihren Bezug als Teil der Geschichte (ADR-0049 §4). PolicyRules.referencing/2 zählt jede Version, auch eine beendete, und der 409 der API sagt dasselbe. Frei wird die Ansicht nur, wenn jede lesende Regel nie gegolten hat und gelöscht wird („Regel löschen“ im Regeldialog). Der Link in A und C führt zur Regel, damit sie gelesen, beendet oder, falls sie noch nicht galt, gelöscht werden kann. Einen Weg zum Löschen der Ansicht verspricht er nicht. ADR-0049 §8 sagte bis zu dieser Planungs-PR das Gegenteil („Retiring the rule first is the remedy“); die Planungs-PR korrigiert den Satz auf das gebaute Verhalten (Sprint-Plan D-6).
  2. Das Bestätigen bleibt. „Diese Ansicht löschen?“ (data-confirm) kommt weiter vor dem Nein, wie beim Wertpapier. Eine Vorabprüfung, die das Löschen gar nicht erst anbietet, ist nicht Gegenstand dieses Boards.
  3. API und MCP: keine Änderung. Der 409 nennt Regel-ID, Name und Stand. Ein Agent erreicht die Regel über ihre ID, und ihr Kontext steht in der Regel selbst.
