Ergebnis — Vorher / Nachher für A und B gleich

Vorher: Eine Umbuchung, deren beide Seiten auf ein Konto oder Depot führen, rollt heute den ganzen Import zurück. Die Meldung ist der Text des Changesets, und jeder künftige Import desselben Exports scheitert genauso. Nachher (§5): Die Umbuchung entfällt und steht in einer eigenen Liste mit Zeile, Art, Datum, Menge oder Betrag und den beiden Namen aus der Datei. Die Duplikate stehen nach ihrer Schicht gruppiert. „Inhalts-Hash“ ist der erwartete Normalfall eines erneuten Imports und bleibt zugeklappt. „Stillgelegter Inhalts-Hash“ (bei einer Zusammenführung entfernt, §3) und die wirtschaftliche Schicht (dieselbe Buchung; nach einer Zusammenführung kann sie eine echte Zwillingsbuchung schlucken, §2) lohnen einen Blick und stehen offen. „Über frühere Namen zugeordnet“ zählt wie heute „über frühere ISIN“ jeden Datensatz, der über diese Stufe aufgelöst wurde (4 aus „Giro“, die 2 Umbuchungen über „Depot 2“), nicht nur die angelegten. Eine gemerkte Zuordnung wird bestätigt, damit sie keine Stammdaten ändert, ohne dass es irgendwo steht. Null neue Konten, weil jede Zeile auf ein bestehendes Konto ging; dass „+ Neu anlegen“ ohne neue Buchung nichts anlegt (§4), zeigt der Randfall unten. Dass „Verrechnungskonten“ über seine Karte hinausläuft, ist der heutige Stand von .import-done .summary, nicht Teil dieser Wahl.
