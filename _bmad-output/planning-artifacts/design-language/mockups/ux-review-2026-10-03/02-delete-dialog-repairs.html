The sentence said “hat 2.504,90 EUR mehr” and then, separately, that the set balance holds — two claims a reader has to reconcile, the first one false for today. R3 — Focus returns to the row's kebab closing the delete dialog and the Edit drawer · WCAG 2.4.3

The dialog's opener, the row menu's item, is gone when the dialog opens, so every exit — Abbrechen, Esc, × — sent the focus to the history's heading, and the browser scrolled the page to the top: the operator lost the row they were on. The Edit drawer (buy/sell and notes-only) has no fallback at all and dropped the focus on <body>. After: the ModalDialog hook returns the focus to the row's kebab while the row exists — the table's at the desktop, the phone row's under 560 px, whichever is visible — and falls back to the heading only when the row is gone (a confirmed delete, A6). A result the close shows (“Notiz gespeichert”, “Transaktion gelöscht: …”) is brought into view below the top bar first; the focus target is then brought into view only if that scroll hid it.

R5 — A split that changed while its dialog was open the split delete, A4 · the merge dialogs' changed-plan form

The confirm ran on the row the dialog was opened from.
