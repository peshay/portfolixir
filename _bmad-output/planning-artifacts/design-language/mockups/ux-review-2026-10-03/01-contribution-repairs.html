The badge colours its whole <p> by the TTWROR's sign (perf_sign_class(@performance.ttwror)), so a positive time-weighted return paints a money loss green — while the contribution table's sum row right below prints the same figure red. A deposit before a fall makes the two signs differ: here the return is +8,5 % and the period's money result −900,90 EUR. After: the money span carries the sign class of the money figure; a zero takes the badge's flat colour.

R4 — A name wraps between words, never mid-word the contribution table's name cell, 561–1024 px

overflow-wrap: anywhere lets the table shrink the name column to its 14ch floor by splitting a word anywhere, and German compounds split at whatever letter reaches the edge: “Fremdwährungsko|nten”, “Abrechnungsdiffer|enzen”. After: break-word breaks inside a word only when the word alone is wider than the cell, and hyphens: auto (the page carries lang) breaks at a syllable with a hyphen where the browser has the language's dictionary — Firefox and Safari ship one, Chrome fetches it. This board's renderer has none, so the After frame shows the plainer result: whole words, and a name column as wide as its longest word (the table's scroller stays the fallback, UX-DR15). Frames at 600 px, the table's width in a ~768 px viewport.

R6 — “p. a.” stays on one line Securities → a security → Trades, the closed trades (#1029)

The basis line breaks between “p.” and “a.” wherever the line ends there — at 1280 px on the German page it did. The column header can do the same when the column is squeezed to its dashes (a security whose trades are all under a year), and the phone row's “· +20,0% p. a.” shares that header's message. After: the three strings carry a no-break space inside “p. a.” (U+00A0, in the gettext msgids and the German msgstrs), so the abbreviation wraps as one word. The frames below are set to the width where the Before line breaks there, measured on the page.
