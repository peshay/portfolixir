The count leaves retired securities out (Catalog.list_securities(is_retired: false)), and the link carries a second condition, filter[]=is_retired:is_false, so the list it opens holds the same three rows. The asset-class finding is the line's one count that is a plain column filter, not a dq predicate: per #700 it is keyed on the stored column. The other predicates make this exclusion in the query; here it has to travel in the URL, and the list shows it. is_retired has no one-tap chip, so the condition is a removable chip in the active-filters band, and “Weitere Filter” counts it. D2: demoting the builder never hides state. Removing the chip brings the retired row back, so the exclusion is visible and reversible, not silent.

Count and list.
