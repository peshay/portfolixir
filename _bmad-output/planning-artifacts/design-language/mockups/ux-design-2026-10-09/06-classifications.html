#1158 — at 390 px an open category's security rows run past the screen before/after

A security row (li.dnd-row, security_row/1) is a nowrap flex line: the name (ellipsized), the ticker, the currency, the quantity and the value; the last two have no rule of their own (app.css:4820-4853, :5313-5319). On a phone the line is wider than the category's body, and .workspace-page { overflow-x: clip } cuts its figures. The cause, found while drawing: the list (ul.cat-securities) is a column flexbox that keeps the base rule's flex-wrap: wrap (app.css:4647), and a wrapping flex line is as wide as its widest item's max-content, so the rows never take the body's width. The spec it applies: DESIGN.md → Phone lists, two-line rows (UX-DR27), "Wealth's Positions" (rule ① of board ux-design-2026-10-04/06-phone-wealth): two tracks, the name (600, wrapping) over its second line, the figures right.

#1187 — the SOLL editor saves targets into an archived plan version before/after

Picking an archived version in "Plan-Version:" loads it with every input enabled and "Plan speichern" live; save_soll_plan/2 sends plan: <id> and Targets.edit_plan/5 writes it (targets.ex:448-462, no status check). Since #1133 the API and MCP refuse the same write ("is archived: activate it, or duplicate it into a draft", target_controller.ex:270). The version hint for an archived plan reads "Archiviert — die Vermögensseite folgt dem aktiven Plan; aktiviere ihn, um ihn wiederzuverwenden.", which neither says the version is read-only nor names the copy. The spec it applies: ADR-0027 §3 and its note of 2026-10-08 ("An archived plan … steers nothing, and is reused by activating it or duplicating it into a draft"); UX-DR17 with the remedy inside the note (H6.1).
