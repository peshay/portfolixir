① Q1 · H45 — the security mapping without the catalog in every row „Wertpapiere aus dem Export“ · security_choice_select/1

The file brings two securities the catalog does not know and one it knows twice. „Sorrel Bay Foods AG“ is new. „Larkspur Rail Holding AG“ is what Portfolio Performance now calls „Larkspur Rail AG“ (a rename the operator recognises; the file's ISIN differs from the stored one, so a remap offers the ISIN change). „Brightwater Utilities SE“ matches two stored securities by name. Today security_choice_select/1 renders <option>s for every security of the catalog (@existing_securities, Catalog.list_securities(is_benchmark: false)) in every row that has a choice: the plain creates, every decision row and every row that books nothing. The page grows with rows × catalog, and every re-render of the preview sends it again.

The cost is the catalog times the rows. A security that needs no decision still carries the whole list; on a phone each opened select is the system's full-screen wheel of every security, alphabetical, with no search. The decision row lists its two candidates as text and then asks the same question again through the whole catalog.

Variante A — one shared datalist; every row a text input

A renders the catalog once, as <datalist id="import-security-options"> under phx-update="ignore", and each row becomes <input list=…> whose empty value means „create“. Against it:

  • The whole catalog still goes to the page, once per preview instead of once per row: the bound is better, not gone.
  • A datalist answers with text, not with a record. The typed or picked label has to be matched back to a security; two securities with one label (twins, the decision row's case) cannot be told apart by the label alone, so the input needs a hidden id beside it and a script to keep the two in step.
  • The suggestions are the browser's: their look, their filtering (prefix or substring), their keyboard behaviour and what a screen reader announces differ between browsers, and on a phone they shrink to the keyboard's suggestion strip. None of it can be styled to the design language or tested by the suite.
  • „Create“ becomes an empty field — the default reads as a missing answer.

Why B.

  • The page carries no catalog at rest. A row that is created as the file names it — the common case — renders one line and one button. The picker exists only in the row the operator opened, and holds only what the search found.
  • It is a picker the app already has. The merge dialog's step 1 searches the catalog server-side („Name, ISIN, WKN oder Ticker“, debounced, capped, nothing suggested before a search) and lists radio cards with each security's currency and ISIN (.search-field, .merge-targets, .merge-target). One search, one card anatomy, one set of tests; the cards keep the 44 px touch floor and the focus ring the merge dialog's closing act gave them.
  • Accessible by construction: a labelled search field and a fieldset of native radios, read and operated the same in every browser and by the suite's LiveView tests; no browser-drawn popup.
  • The decision row answers its own question: its candidates become the first radio cards, with „+ Neu anlegen“ beside them and „Anderes Wertpapier suchen…“ for the rare case that is neither — instead of the candidates as text and then the whole catalog.
  • The default reads as an answer („Wird neu angelegt: Sorrel Bay Foods AG“), and a remap reads as one („Zugeordnet: Larkspur Rail AG · EUR · DE000000001L · Ändern…“). The ISIN-change offer of isin_change_offer/1 follows the chosen target as today.
  • Board 07 stands: N20's recount runs on a remap exactly as on an account choice; a security row's count, where it has one, dims with the cue while the dry run answers.

② Q2 · H57 — a ticker in the file that the catalog refuses Vorschau → „Parser-Warnungen“

The file (JSON, 24 entries) names „Sorrel Bay Foods AG“ with a ticker the catalog's rule refuses (Security.changeset, „is not a ticker symbol“); its buy and two dividends are entries 12, 15 and 21. Today the preview does not apply the ticker rule, so nothing names it; „Import bestätigen“ fails at the security's insert, the whole apply rolls back, and the page's error reads the changeset's message — in English, because the errors domain has no German for it.

Why B. A ticker is the weakest identifier the file carries and the only one the catalog may lack: the security is still matched and created by its ISIN or its name (ADR-0029's tiers), and its bookings are the operator's records. A drops three bookings to protect a field that only the quote sync reads; B keeps every booking, says once what was left out and why, and names the remedy — the ticker set by hand on the security, where the rule's field error explains itself. The warning is a parser warning like the others (#1188's row errors and #1179's „Eintrag“, board 07), so it adds no anatomy. A is the honest alternative if a security without its ticker should never be created silently.
