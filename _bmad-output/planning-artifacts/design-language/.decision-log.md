### Design critique of the live surface (2026-08-01 UAT screenshots, six screens)

The system is coherent at token level and incoherent at component level. Every
recurring UI job has been solved two to five times independently:

| Job | Distinct solutions observed |
| --- | --- |
| "This control is selected" | 5 — solid accent pill · tint + bold text · white-on-grey track with no visible state · solid fill inside a bordered container · tinted table row |
| "Tell the user something about their data" | 4 — plain bullet list · amber inline highlight · unstyled grey prose · accent bordered banner |
| "Show a metric" | 3 — gradient-topped card · flat grey inline strip · unlabelled right-floated tree figure |
| "A negative amount" | 3 — accent violet (KPI) · body ink (rows) · red (total only) |
| "An empty value" | 3 — blank cell · bold em-dash · explanatory prose |
| "Currency" | 3 — inline full-size word · small muted suffix · baked into the value string |
| "A percentage" | 3 — `0.0%` · `0.00 %` · monospace `+1.0 %` |
| "A chip" | 3 — filled tag · outline chip · grey initial-avatar square |
| "A primary action" | 3 — solid button · outline button · invisible grey inline text |
| "Table header" | 2 — uppercase/tracked/rules · sentence-case/no rules |
| "Explain something" | 2, often both at once — ⓘ tooltip AND a prose paragraph |

Three structural themes behind the symptom list:

1. **Prose is the default fallback for anything the design did not solve.** Six
   free-standing explanatory paragraphs across six screens. The worst case: the
   TTWROR explanation exists simultaneously as an ⓘ tooltip and as a paragraph
   on the same screen. UX-DR11 is not occasionally missed — prose is the habit.
2. **Nothing is width- or height-reserved, so the UI moves when used.** Measured:
   securities columns shift 14–21px depending on which row is selected; the
   Wealth tab row shifts 10–11px depending on the active tab; the detail panel's
   tab row moves ~4px depending on the selected security's subtitle length.
   Cause: bold-on-active without reserved metrics.
3. **Native browser controls sit unstyled beside custom ones.** One date input,
   three selects, three `<details>`, one checkbox render in browser default next
   to carefully styled pills and segmented controls. This is where the
   "unfinished" impression concentrates.

Spec violations found in the built UI:

- **Negative amounts render in the accent colour on the Wealth KPI cards.**
  DESIGN.md Colors is explicit: "Gain/loss color never re-keys with the accent —
  money semantics outrank brand." Also no sign emphasis, so UX-DR7's
  colour-independence rule fails on the same element.
- **Semantic colour applied only at totals** — row-level negatives are body ink
  while the total is red.
- **US date format** (`MM/DD/YYYY`) in the native date input, in a product whose
  every display date is ISO.
- **Plural bug**, four occurrences: `portfolio_live.ex:1607, 1612, 1619, 1641`
  use `gettext` with a `%{count}` interpolation instead of `ngettext`, so a
  count of one reads "1 held positions have…". Verified in source.
- **Three absence renderings on one KPI row** (`portfolio_live.ex:715-780`):
  `…` for pending, `—` for not-computable, both bold at value size, visually
  near-identical — so "still loading" and "cannot be computed" are not
  distinguishable. The loading-affordance work must separate them.

Corrected on verification: the critic reported "Gesamt (total)" as an
untranslated German string leaking into the English UI. It is not a defect —
`classifications_live.ex:514` wraps it in `gettext`, and the msgid itself is
"Gesamt (total)". It is a deliberate bilingual domain label. Whether an English
UI should carry a German domain term with a parenthetical gloss is a design
question for the voice section, not a bug.

Two outright visual defects, to be treated as bugs rather than design debt:

- The allocation table header renders two of four headers as white bordered
  boxes with shadow that overflow the header band — they read as stray buttons
  dropped into a header row.
- The classification form's checkbox stack is broken: a bare checkbox alone on
  a line with its label underneath, running into the next field's label.

Other notable findings: the funnel icon means "Views" in the sidebar and
"filter" in the securities toolbar; the sidebar background is viewport-height,
not page-height, leaving a cut edge on long pages; the data-quality section —
the app's most important warning surface — has the lowest visual weight on its
page (bare `<h2>` plus default disc bullets) and its actionable link is styled
identically to surrounding prose; the remedy button for one data-quality
problem sits ~1100px below the bullet naming the problem.

The critic's own priority: unify the selected-state vocabulary and the
alert/callout vocabulary first — five and four competing solutions, both
appearing multiple times per screen, both cheap to unify.

Not verifiable from this set: loading placeholders (no loading state was
captured) and dark-theme behaviour (all six captures are light).

### Session decisions (continued)

- 2026-08-05 — **Selected state reduces to three defined classes.** Navigation
  and tabs → accent underline plus marker. Toggles, filters, period selection →
  segmented group with filled accent. Selection in lists and tables → tinted row
  with a left accent edge. Every control in the app maps to exactly one class.
  Rationale: a selected table row and an active tab are genuinely different
  things; five idioms is drift, one idiom would be dogma.
- 2026-08-05 — **Data notes get three severities in one component.** Note /
  Attention / Problem, distinguished by colour AND icon AND word — never colour
  alone (UX-DR7). Replaces the four competing treatments. Consequence for the
  data-quality list: "valued at last trade price" is a note, "impossible
  negative holding quantity" is a problem; today they render identically.
- 2026-08-05 — **Tabs share one icon vocabulary with the navigation, in two
  idioms.** One icon set app-wide. Sidebar keeps pill plus marker dot; tabs get
  icon plus label plus underline; second-level tabs (inside Cash flow) use the
  same tabs smaller and without icons. The sidebar answers "where am I", tabs
  answer "which facet". Resolves the owner's "text tabs next to an icon menu"
  complaint without making tabs compete with navigation.
- 2026-08-05 — **One period control, per-surface vocabulary.** One defined token
  set (1M 3M 6M YTD 1Y 3Y 5Y Max) and one appearance; each surface declares
  which tokens it offers. "Custom range…" is a disclosure, not permanent chrome.
  Retires the four current patterns, the two divergent token sets, and the four
  bare `type="date"` inputs.
- 2026-08-05 — **The "needs attention" card states its basis, and says so when
  the basis is ambiguous.** A basis line under the heading names view and plan;
  where an allocation carries several plans the card says so explicitly rather
  than silently picking one. Works without active-plan semantics (gated at
  E16/ADR-0027) and improves silently once they exist.
- 2026-08-05 — **Defects ship now, drift ships from the spec.** Verified defects
  become issues immediately and ride Lane B beside #560. Idiom unification is
  cut as Sprint 5 stories from the confirmed spec.
- 2026-08-05 — **Width-reserved active states become a rule.** Bold-on-active
  must reserve its metrics so tab rows and table columns do not shift when
  selection changes. Not a preference — a measured defect on three surfaces.
- 2026-08-05 — **Native controls inherit the design language.** Date inputs,
  selects, `<details>` disclosures and checkboxes get defined appearances
  instead of browser defaults. This is where the "unfinished" impression
  concentrates.

### Draft rule delta for the distillation

Rules move into the spines this session (owner decision above). Beyond

**Amended**

- **UX-DR2** — the "four confirmed metric cards" never shipped as written; the

  rule follows the build or the build follows the rule; it cannot stay as is.
  Flagged for the owner, not silently rewritten.
- **UX-DR4** — the hidden "Soon" nav list is dated by construction and needs

  EXPERIENCE.md's body, becomes part of the numbered rule.
- **UX-DR12** — cross-references the new scroll-container rule.

**New**

- **UX-DR15 — Every wide content block owns its scroller.** `.workspace-page`
  clips rather than scrolls, deliberately, so any block that can exceed the
  viewport (tables, chart label rows, legends) must establish its own
  `overflow-x` container and set `min-width: 0` on flex children. This is the
  system rule behind #560; without it the same defect recurs on the next wide
  table.
- **UX-DR16 — Three selected-state classes.** Navigation and tabs; toggles,
  filters and period selection; selection in lists and tables. Every control
  maps to exactly one.
- **UX-DR17 — Data notes carry one of three severities** — note, attention,
  problem — in one component, distinguished by colour and icon and word.
- **UX-DR18 — Active states are width-reserved.** Bold-on-active must reserve
  its metrics; measured shifts of 10–21px exist on three surfaces today.
- **UX-DR19 — Native controls inherit the design language.** Date inputs,
  selects, `<details>` and checkboxes get defined appearances. Dates render ISO
  in input as well as display.
- **UX-DR20 — Pending and settling are different states.** Reserved for the
  loading-affordance decision; the distinction is settled, the visual treatment

### Session decisions (continued)

- 2026-08-05 — **Count-up gets a ninth inline hook.** Pure-CSS count-up and
  locale-formatted money are mutually exclusive: `counter()` renders `250000`,
  not `250.000,00`. A ~25-line `requestAnimationFrame` + `Intl.NumberFormat`
  LiveView hook in `layout_view.ex` is approved, alongside the eight hooks
  already there. No bundler, no dependency, no architecture change. DESIGN.md's
  Motion section, which assumed CSS `@property` counters, is corrected.
- 2026-08-05 — **Per-instrument income: I2, stacked bars with an aggregated
  remainder.** Largest six instruments individually, everything else as one
  "Sonstige" segment. Carries a constraint to verify: the one-accent-at-a-time
  rule means seven distinguishable segments must be built from tints and shades
  of the active accent plus a neutral. The mockup attempts it; whether it holds
  at the readability limit is a DESIGN.md question, flagged not assumed.
- 2026-08-05 — **UX-DR2 follows the build.** The rule is rewritten to the
  Overview as it exists — value plus change, "Needs attention", data quality —
  rather than the four metric cards confirmed on 2026-06-13 and never built.
  The contradiction has stood since June; this ends it.

- 2026-08-05 — **Loading vocabulary picked: P2 + S1 + F1.**
  - **Pending → P2, last known value dimmed.** The previous value stays on
    screen in muted colour with a recomputing cue and its as-of date, so an
    order of magnitude is visible instead of a void. Consequence to carry: this
    needs a stored previous value per card, and today only TTWROR has one
    (`@stale_ttwror`). Every other card needs that state added, so the
    implementation story is larger than a CSS change. Where no prior value
    exists — first load, a new account — the card falls back to a typographic
    skeleton sized to the value's footprint rather than to a generic block.
  - **Settling → S1, accent bar under the number.** Digits render muted while a
    2px accent bar grows beneath them to full width; on settle the digits snap
    to full colour and the bar fades. Makes progress explicit rather than merely
    implied. Depends on the approved count-up hook — without it the bar would
    have no driver and could only claim to track the count.
  - **Sunburst → F1, sequential clockwise sweep.** Segments appear clockwise as
    their values arrive. Strongest "something is happening" reading. Known cost,
    accepted: the shape moves during the build, so the chart briefly shows
    proportions it does not have. Mitigation to specify in DESIGN.md — the
    build is short and one-shot, and the legend must not settle before the
    geometry does.
  - All three collapse under `prefers-reduced-motion` to the finished state with
    no animation; the pending cue remains as a non-animated indication, since
    loading indication is information rather than polish.

  A first typed pick of P1 + S3 + F3 was corrected by the owner in session to
  P2 + S1 + F1. Recorded so the superseded combination is not mistaken for a
  parallel option later.

### Design-critic findings applied

- **The I2 per-instrument decision was missing from both spines entirely.** The
  owner picked it, the log recorded it, the distillation dropped it. This is the
  same failure this log names two sections earlier as the reason ADR-0038
  exists — repeated inside the session that documents it. Now specified.
- **I2's segment count corrected from six to three plus a remainder.** Seven
  segments from tints of one accent give roughly 1.3:1 between neighbours,
  below the 3:1 non-text floor, and DR7 forbids hue as the sole channel
  regardless. A designer's correction to an owner pick, flagged in place rather
  than applied silently. Small multiples are named as the honest route if six
  named contributors are wanted.
- **Categorical colour is unreconciled and stays that way.** DESIGN.md's closed
  token set, the build's free-form user hex per category
  (`category.ex:15`, rendered straight into the sunburst at
  `portfolio_live.ex:1804`), and this session's accent-tint decision cannot all
  be true. It touches user-set data, so it is a decision gate of its own, not a
  styling call.
- **"Only Income has data today" was wrong.** `TradeMatcher` already returns
  `:closed_trades` with realised P&L per sell, exposed over the JSON API and in
  the Securities detail Trades tab. Realized gains is therefore a presentation
  story over an existing read, not a computation story — which changes Sprint 5
  sizing.
- **The sunburst sweep is decoration, not progress.** Allocation lands from a
  single `start_async(:allocation)`, so every value is known before the first
  frame. The sweep may animate opacity or saturation; it must never animate the
  arc, because a moving arc asserts a share that is false — the standard the
  spec already enforces on digits.
