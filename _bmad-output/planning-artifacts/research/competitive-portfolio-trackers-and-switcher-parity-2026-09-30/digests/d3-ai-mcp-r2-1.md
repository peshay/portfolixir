## Patterns worth adopting
1. **Tool list filtered by scope** (#25): the agent's tool list shows only what its token can call. That means fewer failed calls, and less that an injected instruction can reach.
2. **Separate draft and commit as token scopes** (#5): a credential that can only stage changes is preview-then-apply enforced at the auth layer, not just in the prompt. Ghostfolio dropping a direct create-activity tool in favour of import (#19) fits the same caution, though that reading is interpretation.
3. **Treat content as untrusted for writes** (#15): what the agent reads (tool output, attachments) must never count as authorization to write. This is worth stating as a server-side invariant, not only as prompt wording.
4. **A visible agent audit log with token attribution and Denied outcomes** (#6). Do not repeat Wealthfolio's gap: if "every call is audited" is the promise, the log must not be switchable off (#6 qualification).
5. **Safe defaults for exposure**: bind to loopback on desktop and require auth once the server is network-exposed (#1, #7), and allow browser origins only from the configured public URL (#21).
6. **Copy-paste client configuration** (#2 vs #23): a cheap way to make onboarding easier.
7. **Open space: MCP prompts and resources.** Neither peer ships either (#8, #28). The only finance server found with prompts works on market data alone, not the user's ledger (#33). Versioned MCP prompts over the operator's own ledger, with the no-advice framing inside the template, are unclaimed. Ghostfolio's copy-prompt feature (#29, #30) shows there is demand for a ready-made analysis prompt, and also how advice creeps in through wording like "Optimization Ideas".
8. **Where an "app never calls an LLM" stance stands**: both peers now make LLM calls from inside the app (#14, #31), so that stance is distinct among the two. This digest has no evidence on whether users value it.
9. **Safety evaluation fixtures with rubric grading** (#16) as an idea: for a product that is only an MCP server, the counterpart would be contract tests on tool descriptions and prompt templates. This is speculative.
