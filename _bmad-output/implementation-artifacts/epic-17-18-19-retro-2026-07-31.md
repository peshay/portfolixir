## 2. What went well

**The decision-gate-first pattern earned its keep, three times in a row.**
Every epic put an ADR with owner sign-off before any code. The value is
measurable in E18: the three-method adversarial review of ADR-0029 (red/blue
team, pre-mortem, edge-case walk) surfaced **four blockers at decision time**
— the ADR-0030 position-target class missing from the survival contract, the
stronger-identifier veto, the bidirectional alias-uniqueness guard, the
double-insert repair path. Each of those found in code review instead would
have been a rework round on risk-tier ledger code; found in a document, they
were amendments.

**The closing acts found real defects, not ceremony.** E17's multi-role
review produced the overlay-basis, idempotent fan-out-extend, preview-honesty
and int4-bound fixes (`b977173`); the UAT persona pass produced submit
gating, bookable markers and wizard copy fixes (`a0c341d`). E19's review
round produced an owner requirement mid-flight — a served stale number is
never bare, it always states its basis — which became the provenance-basis
design in the final commit rather than a post-ship complaint.

**External gates caught what the batch missed.** codecov/patch flagged that
the two user-visible results of #607 and #609c had shipped without LiveView
coverage on PR #617; the tests were added before merge. The gate did exactly
its job.

**Honest self-correction happened inside the batch.** ADR-0031's FIFO premise
was found wrong during implementation and corrected in the ADR in the same
batch — the document followed the truth instead of the code quietly diverging
from the document.

**Risk-tier discipline held.** Ledger-math changes (splits booking, identity
ladder, the #611 TTWROR fix) shipped as dedicated PRs with owner review, not
inside batches — including under schedule pressure at the end of Sprint 1.

## 3. What did not go well

**Bookkeeping is not part of the closing act, and it shows everywhere.**
The pattern repeated three times out of three:

- Trackers #338 (E17) and #603 (E18) stayed open after all children merged —
  for over a week, despite the sprint plan explicitly listing their closure.
- #607 and #609 stayed open after their fixes merged.
- `sprint-status.yaml` sat at "awaiting review" after the E19 batch merged;
  `epics.md` still called E19 "gated, sign-off pending" six days after
  sign-off, and FR-36 never entered the FR Coverage Map at all.

None of this is a knowledge problem — every fact was in the merge commit. It
is a process gap: ADR-0026's closing act ends at the reviewer briefing, and
everything after the merge belongs to nobody.

**A required check was red on `main` for a week and nobody noticed.** The
commit-authorship gate failed on every push to `main` from 2026-07-24 to
2026-07-31, because the GitHub UI squash-merge that ADR-0026 itself
prescribes stamps `GitHub <noreply@github.com>` as committer. Policy and
enforcement contradicted each other by construction, and the contradiction
was discovered by an unrelated status check, not by anyone watching CI. A
permanently red gate is worse than no gate: it trains everyone to ignore red.
(Fixed 2026-07-31, `ee51260`: the web-flow committer is accepted for the
committer role only, and only when the author is allowlisted.)

**Issue state lags PR state — the same lesson, learned twice.** The
2026-07-25 sprint plan's first cut called #545 unfixed while the fix sat in
an open PR; the plan itself recorded the lesson. Six days later this
retrospective found #607/#609 open with their fixes merged. The lesson was
written down but not turned into a mechanism, so it repeated.

**Retrospectives did not happen.** Three epic batches completed without one;
`optional` in the tracking file operationally means `never`. This document
exists because the owner asked, not because the process fired.

## 5. Key insights

1. **Gates before code work.** Decisions reviewed as documents absorb
   blockers cheaply; the same blockers in code are rework. Keep the pattern
   for anything money-domain, keep the adversarial review on the ADR itself.
2. **The batch ends at the merge, but the epic doesn't.** Every observed
   failure of the period sits *after* the reviewer briefing: trackers, issue
   closure, planning artifacts, watching the merge's own CI. The closing act
   needs a final step that owns the aftermath.
3. **An always-red gate is a process bug of the highest priority**, because
   its cost is silent: it erodes the signal value of every other gate.
4. **Lessons need mechanisms, not prose.** Twice-learned lessons stayed
   prose. Where a lesson can be a checklist item, a hook, or a required
   check, make it one.

## 6. Action items

No time estimates by design; sequencing only.

1. **Extend the ADR-0026 closing act with a bookkeeping close-out.**
   After merge, in the same pass as the reviewer briefing: update
   `sprint-status.yaml` and `epics.md` (including the FR Coverage Map), close
   the story issues and the epic tracker, and confirm the merge's own CI runs
   are green — required checks included.
   *Owner:* the agent running the batch. *Done when:* the next epic batch
   leaves no tracker outliving its children and no planning artifact
   describing a pre-merge state. *Mechanism:* amend the Epic-Batch Workflow
   section in AGENTS.md (step 3) so the close-out is part of the definition,
   not a memory.
2. **Verify the authorship-gate fix on the next squash-merge to `main`.**
   `ee51260` must turn the required check green; if any required check is red
   on two consecutive pushes to `main`, treat it as an incident.
   *Owner:* maintainer (one look at the checks tab). *Done when:* the next
   merge shows a green "Commit authorship" run.
3. **Sprint planning consults PRs and CI, never issue state alone.** Already
   practiced in the 2026-07-31 plan; codify it as a standing input rule in
   the sprint-planning customization so it survives agent turnover.
   *Owner:* PM agent. *Done when:* the rule lives in
   `_bmad/custom/bmad-sprint-planning.toml` rather than in a dated plan file.
4. **Retrospective per epic batch, inside the closing act.** Not a separate
   optional ritual: a short evidence-based retro section in the reviewer
   briefing satisfies it for small batches; a session like this one for
   larger arcs. *Owner:* PM agent proposes, owner disposes. *Done when:* the
   next epic batch's briefing carries a retro section, and its
   `epic-N-retrospective` key flips to done with the merge.
5. **Owner UAT walkthrough of the tax entry surface (19.6).** New
   user-visible money-domain surface; the UAT-persona pass ran on synthetic
   data, but the owner walkthrough on the live instance is the acceptance
   ADR-0026 defines, and the existing `needs-uat` pile should not silently
   absorb it. *Owner:* the maintainer, on the live instance. *Done when:* feedback
   lands as a UAT fix round or an explicit "accepted as shipped".
